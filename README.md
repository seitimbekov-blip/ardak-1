# Сверка и заливка лотов плана закупок

Инструмент автоматизирует сверку выгрузки плана закупок из **SAP** и выгрузки
с **Портала закупок Фонда** (или ИСЭЗ 2.0 — формат равнозначен), рассчитывает
статус каждого лота (ДОБАВИТЬ / ИЗМЕНИТЬ / ИСКЛЮЧИТЬ / БЕЗ ИЗМЕНЕНИЙ) и
готовит файл для последующей автозаливки скриптом `em_agent.py` на
zakup.sk.kz. Реализовано по PRD `docs/prd.md`-эквиваленту, MVP для одного
локального пользователя.

## Установка

```bash
pip install -r requirements.txt
```

## Запуск UI

```bash
streamlit run app.py
```

Откроется локальная страница: загрузите файл SAP и файл Портала, нажмите
«Сравнить», просмотрите результат и аномалии, скачайте:
- полный отчёт с цветовой подсветкой статусов;
- файл, готовый для `em_agent.py` (колонка «Тип действия» заполнена
  рассчитанным, а не справочным значением).

История запусков (дата, кол-во лотов по статусам, число аномалий)
сохраняется в `history/runs.jsonl` и доступна во вкладке «История запусков».

## Тесты

```bash
pytest
```

Тесты используют синтетические `.xlsx`-фикстуры (генерируются "на лету" в
`tests/conftest.py`) и покрывают: парсинг номера лота, определение
актуальной версии лота в SAP, все 4 статуса сверки, аномалии (F4), экспорт
отчёта и файла для `em_agent.py`.

## Структура

```
lot_reconciler/
  lot_parser.py     — разбор номера лота (базовый номер / версия / вид Т,Р,У)
  models.py         — структуры данных (LotRecord, ComparisonResult, ...)
  excel_utils.py     — поиск колонок по заголовкам (в т.ч. многоуровневым)
  sap_loader.py       — загрузка выгрузки SAP, определение актуальной версии
  portal_loader.py    — загрузка выгрузки Портала/ИСЭЗ, пропуск строк-категорий
  compare.py           — сопоставление и расчёт статуса
  export.py            — экспорт отчёта и файла для em_agent.py
  history.py           — лог запусков (F10)
  pipeline.py           — связывает загрузку/сверку/лог в одну функцию
config/field_aliases.json — маппинг канонических полей на колонки Excel
app.py                     — Streamlit UI
```

## Допущения и ограничения (важно прочитать перед первым запуском на боевых файлах)

1. **Фиксированные колонки** заданы по PRD: SAP — номер лота колонка A, «Тип
   действия» колонка B, сумма без НДС колонка AE; Портал — номер лота
   колонка B, сумма без НДС колонка S.
2. **Остальные поля сравнения** (срок закупки, кол-во, цена за единицу,
   приоритет, способ закупок, адрес, условия поставки/оплаты, сумма с НДС)
   ищутся автоматически по тексту заголовка (см. `config/field_aliases.json`,
   алиасы на русском). Если реальные заголовки в файлах отличаются —
   отредактируйте алиасы в этом файле (colонки искать не нужно, только
   подстроки заголовка). Поля, которые не удалось найти, помечаются как
   аномалия «unresolved_sap_columns» / «unresolved_portal_columns» и просто
   не участвуют в сравнении — сверка не блокируется.
3. **Формат файла для `em_agent.py`** реализован по лучшему приближению без
   доступа к исходному коду `em_agent.py` (его нет в этом репозитории): для
   ДОБАВИТЬ/ИЗМЕНИТЬ используется полная исходная строка SAP с перезаписанной
   колонкой «Тип действия»; для ИСКЛЮЧИТЬ (лота уже нет в SAP) строка
   собирается из полей Портала, перенесённых в колонки SAP по маппингу.
   **Перед первой реальной заливкой стоит свериться, что структура колонок
   совпадает с тем, что ожидает ваш `em_agent.py`**, и при необходимости
   скорректировать `lot_reconciler/export.py`.
4. Строки-разделители категорий на Портале («1. Товары», «2. Работы»,
   «3. Услуги») распознаются по тексту в любой ячейке строки с пустой
   колонкой номера лота и пропускаются без ошибок.
5. Один и тот же базовый номер + вид закупки — ключ сопоставления (версия в
   номере лота в ключе не участвует, только для определения актуальности в
   SAP).
